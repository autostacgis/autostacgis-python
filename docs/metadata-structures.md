# Declared metadata structures

`metadata_structure` is a sibling of `catalog` and `request` in a configuration. It combines HTTPS STAC Item JSON Schema references and a manual Item JSON Schema:

```json
{
  "metadata_structure": {
    "schemas": ["https://stac-extensions.github.io/eo/v2.0.0/schema.json"],
    "inline": {
      "properties": {
        "properties": {
          "properties": {
            "quality": {"type": "number", "minimum": 0, "maximum": 1},
            "autostacgis:source_item_id": {"type": "string"}
          }
        }
      }
    },
    "strict": true
  }
}
```

The schema describes the entire STAC Item, so custom Item metadata is nested under `properties.properties`. Asset metadata is under `properties.assets.additionalProperties.properties`. Core STAC Item fields are always included. Reference all extension schemas used by the workflow, including `data_state` when processing declares data-state metadata. Normal STAC extension validation still requires the Item to declare its `stac_extensions` appropriately.

When present, this section defaults to strict validation: every object field must be declared, including nested properties and asset fields. `additionalProperties: true` does not declare arbitrary fields. Use `patternProperties` for deliberate dynamic names, or an object-valued `additionalProperties` schema for dictionaries such as assets. Types and constraints in referenced and manual schemas are validated too. `strict: false` disables only unknown-field rejection. Existing configurations that omit the section retain standard STAC validation for compatibility.

The same configuration follows discovery, processing pool tasks, checkpoints and timed/file triggers. Input and generated output Items are validated by the shared STAC validator. The PostgreSQL publisher adds `properties.autostacgis:source_item_id`; declare it when using strict publication. Other fields generated by processing plugins also need declarations.

Plugins can inspect the structure without parsing the configuration:

```python
fields = context.metadata_structure.fields(("properties",))
quality_declarations = fields.get("quality", [])
asset_fields = context.metadata_structure.fields(("assets", "data"))
configuration = context.metadata_structure.definition()  # defensive copy
context.stac.validate(item)  # core, extension, configured schema and strict checks
```

`fields()` resolves `$ref`, composition branches and dynamic dictionaries, returning field names mapped to their schema declarations. Referenced schemas reuse the STAC schema cache and configured local schema overrides; missing remote schemas load over HTTPS with a timeout. A schema reference need not be re-downloaded for each field inspection in that STAC context.

Both web and QGIS expose this structure in a Metadata Structure tab and save/import/export it with the workflow. Their tree/text JSON editors retain JSON types and preserve invalid raw drafts for correction.
